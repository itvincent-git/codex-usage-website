## 新手需要先改这些设置吗

一般不需要。先使用自动发现和系统时区；只有会话目录不在默认位置、找不到 CLI，或希望按固定时区统计时，再调整环境变量。主题、语言和日常桌面行为则可以直接在“设置”中修改。

## 先配置日常使用习惯

- **主题与语言**：选择浅色或深色，以及适合你的界面语言。
- **登录时启动**：希望开机登录后即可查看用量时开启。
- **自动检查更新**：用于获知可用的新版本。
- **菜单栏 / 系统托盘**：选择显示的额度内容和倒计时单位，让工作时也能看到剩余额度。

调整菜单栏或托盘显示后，到对应位置确认文字是否清晰、是否包含你关心的窗口。实时额度的含义见[额度指南](/zh/docs/quota/)。

## 指定 Codex 数据与 CLI

**`CODEX_HOME`** 指定 Codex 主目录，而不是某一个 JSONL 文件。非空值会覆盖默认目录，并关闭 Windows / WSL 自动发现。只有明确知道目标日志在哪里时才设置，避免应用切换到空目录。

**`CODEX_CLI_PATH`** 指定 Codex CLI 可执行文件或包装器，例如 `codex`、`codex.exe`、`codex.cmd`。在应用无法发现 CLI 或你使用自定义安装位置时才需要指定。

这两个变量分别控制“从哪里读日志”和“使用哪个 CLI”，不要混淆。环境变量需要由启动应用的进程继承；只在某个终端中设置，并不保证从桌面图标启动的应用能读到它。

## 固定每日统计的时区

**`CODEX_USAGE_TIMEZONE`** 控制每日统计的日期分组，默认使用系统时区，获取失败时回退为 UTC。跨时区工作或对齐报告日期时，可以明确指定，例如 `Asia/Shanghai` 或 `UTC`。

时区变化可能让午夜附近的用量归入相邻日期。比较看板或导出数据时，应同时核对时区与日期范围。

## 修改后如何确认生效

1. 记下修改前的目录选择与统计范围，方便恢复。
2. 确保启动应用的环境能读取这些变量，然后完全退出并重新打开应用。
3. 重新扫描本地日志，检查目标日期内的会话数量和项目是否符合预期。
4. 若数据反而缺失，移除自定义覆盖后重启，再检查[故障排查](/zh/docs/troubleshooting/)。
