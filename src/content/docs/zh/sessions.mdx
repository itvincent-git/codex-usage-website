## 什么时候查看会话

当你想知道“一次任务到底用了多少”“用量升高时 Codex 在做什么”，可以从会话列表进入具体记录。会话是本地 Codex 日志中的工作记录，详情能展示的内容取决于日志实际写入了什么。

## 找到要看的那一次工作

1. 打开“会话”，选择覆盖目标工作的日期范围。
2. 按日期浏览，先看每天的 Token 总量，再看当天的各段会话。
3. 用标题、项目或模型搜索，缩小到相关记录。
4. 对比总 Token、输入、缓存、输出与预估成本，打开你想调查的会话。

从项目详情也能进入会话。如果列表为空，先清空搜索并扩大日期范围，再检查[日志发现与扫描](/zh/docs/troubleshooting/)。

## 先读摘要，再沿时间线查看

打开详情后，先确认会话标题、Token 总量与构成，随后按时间线浏览活动。日志中有记录时，你可以看到命令与工具、网页搜索与结果、补丁与差异、长时间运行的命令、子代理层级以及剩余额度变化。

用量节点会显示两类数值：

- **累计 Token**：截至这次记录已经累计的用量。
- **新增 Token**：相对上一次用量记录增加的部分。

> 虚构示例：相邻两次累计数为 80,000 和 95,000，后一次新增为 15,000。不能把 80,000 与 95,000 相加作为会话总量。

输入已包含缓存输入。排查一次明显的用量增长时，可以先找新增量较大的节点，再阅读相邻活动。一个节点覆盖的是两次记录之间的变化，不一定能把所有 Token 精确归到某一条命令。

## 会话中的额度百分比是什么意思

列表和详情中的 5 小时与每周百分比，是**这段会话的预估额度消耗量**。只有日志包含足够的额度记录时才能估算，不是 Token 数量的直接换算。

它们与看板中“当前剩余额度”的方向不同。缺少估算值表示记录不足，不表示没有消耗。多个会话同时运行时，额度变化也可能受到其他工作的影响。

## 什么时候需要原始 JSONL

当摘要或时间线无法解释某条记录时，可以通过详情里的 JSONL 链接核对源日志。JSONL 是逐行保存的日志格式；日常阅读通常使用时间线即可，无需编辑原始文件。

截图或分享内容前，请遮盖会话标题、项目路径、提示词、代码、命令、账户信息等私密细节。需要分享汇总时，可先考虑[导出统计](/zh/docs/export/)，并在分享前检查文件。
