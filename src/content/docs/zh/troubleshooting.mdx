## 先判断是哪一类问题

Token 统计来自本地日志，实时额度需要账户身份验证和网络，预估成本还依赖模型价格。因此“有会话但没有额度”或“有 Token 但成本为零”可以分别排查。

## 看不到会话或总量偏少

1. 在平时使用 Codex 的环境里完成一次交互，确认已经产生 JSONL 日志。
2. 清空会话搜索，扩大日期范围，避免记录只是被筛掉。
3. 使用“重新扫描本地日志”，等扫描完成后再次查看。
4. 检查是否设置了 `CODEX_HOME`，它会覆盖自动发现。变量调整后需要重启应用。
5. Windows 用户核对[原生与 WSL 的发现顺序](/zh/docs/windows-wsl/)。两边的数据不会合并；其他电脑上的记录也不会自动出现。

如果只是午夜附近的记录落在前一天或后一天，请检查系统时区与 `CODEX_USAGE_TIMEZONE`，详见[进阶设置](/zh/docs/advanced-settings/)。不要通过修改或删除源日志来修正显示问题。

## 会话有记录，但实时额度不可用

1. 确认网络可用。
2. 确认应用所使用的 Codex CLI 已登录；必要时在相同环境执行 `codex login`。
3. 返回应用重新查询额度。
4. 若使用了自定义 CLI 安装位置，检查 `CODEX_CLI_PATH`，修改后重启。

查询额度本身不消耗模型额度；无需通过“启动额度窗口”排查查询失败。

## 成本为零，或不同页面数值不同

模型没有可用定价时，预估成本默认为零。到“模型 → 价格目录”搜索模型并刷新价格；零估算不能证明使用免费。

比较页面前，核对日期范围、时区和筛选条件。输入包含缓存，不能重复相加；会话额度消耗估算也不能与账户当前剩余百分比直接比较。请参阅[看板指标](/zh/docs/dashboard/)和[会话指南](/zh/docs/sessions/)。

## 安装时被系统提示拦截

Windows 安装包尚未进行 Authenticode 签名，SmartScreen 可能警告。先确认安装包来自项目 GitHub Release。macOS 若被 Gatekeeper 阻止首次启动，在“系统设置 → 隐私与安全性”中允许应用，不要关闭或绕过 Gatekeeper。

## 仍然无法解决时，如何反馈

查看[项目 Issues](https://github.com/itvincent-git/codex-usage-desktop/issues)，已有相同问题时可参考其中的处理方式。提交新报告时，提供：

- 操作系统、芯片架构和应用版本。
- Codex 运行于原生环境还是 WSL，是否自定义路径或时区。
- 复现步骤、预期结果和实际结果，以及重新扫描后是否仍然出现。
- 已遮盖私人信息的错误提示或必要诊断内容。

不要公开账户、密钥、绝对路径、私人项目名或完整会话日志。需要截图时，先按[隐私指南](/zh/docs/privacy/)检查再分享。
