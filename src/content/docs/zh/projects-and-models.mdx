## 想找用量来源，从这里开始

看板告诉你总共用了多少，“项目”回答“用在哪项工作上”，“模型”回答“由哪些模型产生”。先选择要调查的日期范围，再比较，避免把不同时间段的结果放在一起。

## 按项目定位工作

1. 打开“项目”，查看项目名称与目录。名称相近时，用路径区分不同工作目录。
2. 先按总 Token 降序排序，找到用量最多的项目；想了解成本来源时，改按成本排序。
3. 查看该行的每日 Token 柱状图、成本趋势线与 Token 构成，判断是某一天集中使用还是持续产生用量。
4. 点击项目打开详情，在所选范围内查看分析和按天分组的会话；展开日期，搜索并打开具体会话。

还可以按项目名称、最近使用时间、输入、缓存或输出排序，并切换升序与降序。彩色成本条用于比较各项目的相对大小，不能当成账户额度警报。

Token 构成中的未缓存输入、缓存输入和输出互不重复。若查看的是“输入（含缓存）”，就不要再叠加缓存数值。

## 按模型比较用量和价格

打开“模型”的“用量分析”，先看活跃模型、Token 占比与成本占比，再查看模型比较表。可以按总 Token、预估成本或有效单价排序。

- **标准单价**：每百万未缓存输入、缓存输入或输出 Token 的参考价格，三类单价应分别阅读。
- **有效单价**：该模型预估成本除以总 Token，再换算成每百万 Token，反映当前输入、缓存、输出构成下的综合结果。
- **预估成本**：由模型定价和实际用量构成共同决定。因此 Token 最多的模型不一定成本最高。

模型名来自本地日志。没有可用定价的模型预估成本默认为零；零成本不能证明这部分使用免费。

## 模型额度消耗估算怎么看

数据足够时，模型页还会估算所选时段内各模型消耗的 5 小时与每周额度，并给出每百万 Token 的消耗作为比较参考。

估算依据单一模型会话中的历史额度快照。快照为整数百分比，界面会提供误差范围；同时运行的其他会话也可能影响归因。“暂无可归因快照”表示证据不足，不表示该模型不消耗额度。这个区域不能替代[实时额度](/zh/docs/quota/)。

## 查价格目录

切换到“价格目录”，按模型或供应商搜索，必要时使用供应商筛选和“刷新价格”。目录的单位是美元 / 百万 Token，收录的模型不一定是你使用过的模型。离线时可能只显示有限的内置价格。

定位到主要项目后，继续用[会话指南](/zh/docs/sessions/)追查具体任务；需要保留比较结果时，可[导出所选范围](/zh/docs/export/)。
