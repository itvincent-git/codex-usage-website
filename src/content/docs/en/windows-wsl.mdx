## Who should read this

Use this guide if Codex runs on Windows 10/11 x64 or in a WSL terminal. Automatic discovery normally works without configuring paths, but it selects one source of logs.

## Discovery order

1. The app uses a directory previously saved through **Choose Codex directory** first. Otherwise, it uses a non-empty `CODEX_HOME` if set.
2. With neither override set, it checks `%USERPROFILE%\.codex` for `.jsonl` and `.jsonl.zst` files under `sessions` and `archived_sessions`.
3. If no native session files are found, it tries the default WSL distribution's `$HOME/.codex`. If WSL is unavailable, it falls back to the native directory.

Native and WSL sessions are not combined. Multiple WSL distributions are not merged, preventing duplicate totals.

## WSL work is missing

First check whether the distribution you use is the default. This read-only command in Windows PowerShell lists distributions; an asterisk marks the default:

```powershell
wsl --list --verbose
```

Confirm that the distribution contains Codex sessions. During automatic discovery, any supported session file under the native Windows directory takes priority.

If the recovery panel offers **Choose Codex directory**, select the WSL Codex home containing `sessions` or `archived_sessions`. The app saves the choice and rescans immediately. You can also set `CODEX_HOME` to a Windows-accessible WSL path such as `\\wsl.localhost\Ubuntu\home\example\.codex`. See [Advanced settings](/docs/advanced-settings/) for how to apply it.

## Installation and live limits

The installer runs for the current user. It is not yet Authenticode-signed, so SmartScreen may warn. Verify the file came from the project GitHub release linked by the [download page](/download/).

If sessions appear but limits do not, check that Codex CLI in the environment being used is signed in. Local log access and live quota retrieval are separate operations; see [troubleshooting](/docs/troubleshooting/).
