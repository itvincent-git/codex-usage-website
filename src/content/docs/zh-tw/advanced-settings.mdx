## 新手需要先改這些設定嗎

一般不需要。先使用自動發現和系統時區；只有工作階段目錄不在預設位置、找不到 CLI，或希望按固定時區統計時，再調整環境變數。主題、語言和日常桌面行為則可以直接在「設定」中修改。

## 先設定日常使用習慣

- **主題與語言**：選擇淺色或深色，以及適合你的介面語言。
- **登入時啟動**：希望開機登入後即可檢視用量時開啟。
- **自動檢查更新**：用於獲知可用的新版本。
- **選單列 / 系統匣**：選擇顯示的額度內容和倒數計時單位，讓工作時也能看到剩餘額度。

調整選單列或系統匣顯示後，到對應位置確認文字是否清晰、是否包含你關心的視窗。即時額度的含義見[額度指南](/zh-tw/docs/quota/)。

## 指定 Codex 資料與 CLI

**`CODEX_HOME`** 指定 Codex 主目錄，而不是某一個 JSONL 檔案。非空值會覆蓋預設目錄，並關閉 Windows / WSL 自動發現。只有明確知道目標記錄在哪裡時才設定，避免應用程式切換到空目錄。

**`CODEX_CLI_PATH`** 指定 Codex CLI 可執行檔案或包裝器，例如 `codex`、`codex.exe`、`codex.cmd`。在應用程式無法發現 CLI 或你使用自訂安裝位置時才需要指定。

這兩個變數分別控制「從哪裡讀記錄」和「使用哪個 CLI」，不要混淆。環境變數需要由啟動應用程式的程序繼承；只在某個終端機中設定，並不保證從桌面圖示啟動的應用程式能讀到它。

## 固定每日統計的時區

**`CODEX_USAGE_TIMEZONE`** 控制每日統計的日期分組，預設使用系統時區，取得失敗時回退為 UTC。跨時區工作或對齊報告日期時，可以明確指定，例如 `Asia/Shanghai` 或 `UTC`。

時區變化可能讓午夜附近的用量歸入相鄰日期。比較儀表板或匯出資料時，應同時核對時區與日期範圍。

## 修改後如何確認生效

1. 記下修改前的目錄選擇與統計範圍，方便恢復。
2. 確保啟動應用程式的環境能讀取這些變數，然後完全結束並重新開啟應用程式。
3. 重新掃描本機記錄，檢查目標日期內的工作階段數量和專案是否符合預期。
4. 若資料反而缺失，移除自訂覆蓋後重新啟動，再檢查[疑難排解](/zh-tw/docs/troubleshooting/)。
