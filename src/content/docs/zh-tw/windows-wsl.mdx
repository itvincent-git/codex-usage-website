## 適合哪些使用者

如果你在 Windows 10/11 x64 上使用 Codex，或者平時在 WSL 終端機裡執行 Codex，請先了解應用程式會選擇哪份記錄。通常安裝後即可自動發現，無需一開始就設定路徑。

## 自動發現順序

1. 應用程式優先使用透過**選擇 Codex 目錄**儲存的目錄。其次使用已設定的非空 `CODEX_HOME`。
2. 未手動指定目錄時，應用程式先在 `%USERPROFILE%\.codex` 的 `sessions` 和 `archived_sessions` 中尋找 `.jsonl` 和 `.jsonl.zst` 檔案。
3. 找不到原生工作階段檔案時，應用程式會嘗試使用預設 WSL 發行版的 `$HOME/.codex`。若 WSL 無法使用，則回到原生目錄。

Windows 原生與 WSL 工作階段不會合併，多個 WSL 發行版也不會合併，以避免重複統計。

## 在 WSL 中工作卻看不到工作階段

先確認你平時使用的發行版是不是預設發行版。在 Windows PowerShell 中執行以下唯讀命令，可以列出發行版，帶星號的項目為預設項目：

```powershell
wsl --list --verbose
```

確認該發行版中已有 Codex 工作階段。自動發現時，只要 Windows 原生目錄中存在支援的工作階段檔案，就會優先使用原生目錄。

如果復原面板提供**選擇 Codex 目錄**，請選取包含 `sessions` 或 `archived_sessions` 的 WSL Codex 主目錄。應用程式會儲存選擇並立即重新掃描。也可將 `CODEX_HOME` 設為 Windows 可存取的 WSL 路徑，例如 `\\wsl.localhost\Ubuntu\home\example\.codex`。設定方式見[進階設定](/zh-tw/docs/advanced-settings/)。

## 安裝與即時額度

Windows 安裝檔按目前使用者安裝。由於尚未進行 Authenticode 簽章，SmartScreen 可能顯示「無法辨識的應用程式」，繼續前請確認檔案來自[官方下載入口](/zh-tw/download/)指向的專案 GitHub Release。

如果能看到工作階段但無法查詢額度，請確認應用程式所使用環境中的 Codex CLI 已登入，再查詢。記錄讀取成功與帳戶額度查詢成功是兩件獨立的事，更多步驟見[疑難排解](/zh-tw/docs/troubleshooting/)。
