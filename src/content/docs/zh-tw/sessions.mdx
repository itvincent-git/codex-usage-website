## 什麼時候檢視工作階段

當你想知道「一次任務到底用了多少」「用量升高時 Codex 在做什麼」，可以從工作階段清單進入具體記錄。工作階段是本機 Codex 記錄中的工作記錄，詳細資料能展示的內容取決於記錄實際寫入了什麼。

## 找到要看的那一次工作

1. 開啟「工作階段」，選擇覆蓋目標工作的日期範圍。
2. 按日期瀏覽，先看每天的 Token 總量，再看當天的各個工作階段。
3. 用標題、專案或模型搜尋，縮小到相關記錄。
4. 對比總 Token、輸入、快取、輸出與預估成本，開啟你想調查的工作階段。

從專案詳細資料也能進入工作階段。如果清單為空，先清空搜尋並擴大日期範圍，再檢查[記錄發現與掃描](/zh-tw/docs/troubleshooting/)。

## 先讀摘要，再沿時間軸檢視

開啟詳細資料後，先確認工作階段標題、Token 總量與構成，隨後按時間軸瀏覽活動。記錄包含相關資訊時，你可以看到命令與工具、網頁搜尋與結果、修補程式與差異、長時間執行的命令、子代理程式層級以及剩餘額度變化。

用量節點會顯示兩類數值：

- **累計 Token**：截至這次記錄已經累計的用量。
- **新增 Token**：相對上一次用量記錄增加的部分。

> 虛構範例：相鄰兩次累計數為 80,000 和 95,000，後一次新增為 15,000。不能把 80,000 與 95,000 相加作為工作階段總量。

輸入已包含快取輸入。排查一次明顯的用量增長時，可以先找新增量較大的節點，再閱讀相鄰活動。一個節點覆蓋的是兩次記錄之間的變化，不一定能把所有 Token 精確歸到某一條命令。

## 工作階段中的額度百分比是什麼意思

清單和詳細資料中的 5 小時與每週百分比，是**這個工作階段的預估額度消耗量**。只有記錄包含足夠的額度記錄時才能估算，不是 Token 數量的直接換算。

它們與儀表板中「目前剩餘額度」的方向不同。缺少估算值表示記錄不足，不表示沒有消耗。多個工作階段同時執行時，額度變化也可能受到其他工作的影響。

## 什麼時候需要原始 JSONL

當摘要或時間軸無法解釋某條記錄時，可以透過詳細資料裡的 JSONL 連結核對原始記錄。JSONL 是逐行儲存的記錄格式；日常閱讀通常使用時間軸即可，無需編輯原始檔案。

截圖或分享內容前，請遮蓋工作階段標題、專案路徑、提示文字、程式碼、命令、帳戶資訊等私密細節。需要分享彙總時，可先考慮[匯出統計](/zh-tw/docs/export/)，並在分享前檢查檔案。
