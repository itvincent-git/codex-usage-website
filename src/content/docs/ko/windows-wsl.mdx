## 이 가이드가 필요한 경우

Windows 10/11 x64 또는 WSL 터미널에서 Codex를 사용한다면 읽어보세요. 보통 경로 설정 없이 자동 탐색이 동작하지만 로그 출처는 하나만 선택합니다.

## 탐색 순서

1. 앱에서 **Codex 디렉터리 선택**으로 저장한 디렉터리를 먼저 사용합니다. 그다음 비어 있지 않은 `CODEX_HOME`이 설정되어 있으면 해당 경로를 사용합니다.
2. 직접 지정한 경로가 없으면 `%USERPROFILE%\.codex`의 `sessions`와 `archived_sessions`에서 `.jsonl` 및 `.jsonl.zst` 파일을 찾습니다.
3. 네이티브 세션 파일이 없으면 기본 WSL 배포판의 `$HOME/.codex`를 사용해 봅니다. WSL을 사용할 수 없으면 네이티브 디렉터리로 돌아갑니다.

네이티브 세션과 WSL 세션은 합쳐지지 않습니다. 여러 WSL 배포판도 병합하지 않으므로 합계 중복을 방지합니다.

## WSL 작업이 누락된 경우

사용하는 배포판이 기본 배포판인지 먼저 확인하세요. Windows PowerShell에서 다음 읽기 전용 명령을 실행하면 목록이 표시되며 별표가 기본 배포판을 나타냅니다.

```powershell
wsl --list --verbose
```

해당 배포판에 Codex 세션이 있는지 확인하세요. 자동 탐색에서는 Windows 네이티브 디렉터리에 지원되는 세션 파일이 하나라도 있으면 해당 디렉터리가 우선됩니다.

복구 패널에 **Codex 디렉터리 선택**이 표시되면 `sessions` 또는 `archived_sessions`가 있는 WSL Codex 홈을 선택하세요. 앱이 선택을 저장하고 즉시 다시 스캔합니다. `CODEX_HOME`을 `\\wsl.localhost\Ubuntu\home\example\.codex`처럼 Windows에서 접근 가능한 WSL 경로로 지정할 수도 있습니다. 적용 방법은 [고급 설정](/ko/docs/advanced-settings/)을 참고하세요.

## 설치 및 실시간 한도

설치 프로그램은 현재 사용자에게 설치합니다. 아직 Authenticode 서명이 없어 SmartScreen 경고가 나타날 수 있습니다. [다운로드 페이지](/ko/download/)에 연결된 프로젝트 GitHub 릴리스에서 받은 파일인지 확인하세요.

세션은 표시되지만 한도가 없다면 사용하는 환경의 Codex CLI 로그인 상태를 확인하세요. 로컬 로그 접근과 실시간 한도 조회는 별개입니다. [문제 해결](/ko/docs/troubleshooting/)을 참고하세요.
