## 이 가이드가 필요한 경우

Windows 10/11 x64 또는 WSL 터미널에서 Codex를 사용한다면 읽어보세요. 보통 경로 설정 없이 자동 탐색이 동작하지만 로그 출처는 하나만 선택합니다.

## 탐색 순서

1. 먼저 `%USERPROFILE%\.codex`에서 Windows 네이티브 JSONL 세션을 확인합니다.
2. 네이티브 세션이 없을 때만 기본 WSL 배포판의 `$HOME/.codex` 데이터와 Codex CLI를 확인합니다.
3. 비어 있지 않은 `CODEX_HOME`은 선택된 디렉터리를 재정의하고 Windows/WSL 자동 탐색을 비활성화합니다.

네이티브 세션과 WSL 세션은 합쳐지지 않습니다. 여러 WSL 배포판도 병합하지 않으므로 합계 중복을 방지합니다.

## WSL 작업이 누락된 경우

사용하는 배포판이 기본 배포판인지 먼저 확인하세요. Windows PowerShell에서 다음 읽기 전용 명령을 실행하면 목록이 표시되며 별표가 기본 배포판을 나타냅니다.

```powershell
wsl --list --verbose
```

해당 배포판에 Codex 세션이 있는지 확인하세요. Windows 네이티브 디렉터리에도 JSONL 세션이 있다면 최근 작업 대부분이 WSL에서 이루어졌더라도 네이티브 세션을 우선 사용합니다.

특정 Codex 홈을 지정하려면 [고급 설정](/ko/docs/advanced-settings/)의 `CODEX_HOME`을 참고하고 앱을 다시 시작한 뒤 재스캔하세요. 자동 탐색 방식을 바꾸려고 기존 로그를 삭제하지 마세요.

## 설치 및 실시간 한도

설치 프로그램은 현재 사용자에게 설치합니다. 아직 Authenticode 서명이 없어 SmartScreen 경고가 나타날 수 있습니다. [다운로드 페이지](/ko/download/)에 연결된 프로젝트 GitHub 릴리스에서 받은 파일인지 확인하세요.

세션은 표시되지만 한도가 없다면 사용하는 환경의 Codex CLI 로그인 상태를 확인하세요. 로컬 로그 접근과 실시간 한도 조회는 별개입니다. [문제 해결](/ko/docs/troubleshooting/)을 참고하세요.
