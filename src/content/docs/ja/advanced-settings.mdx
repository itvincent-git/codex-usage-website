## 初心者も変更が必要？

通常は自動検出とシステムのタイムゾーンで使えます。環境変数は、ログが別の場所にある、CLI が見つからない、報告の時区を固定したい場合に調整します。日常の表示や動作は設定画面から変えられます。

## 日常の設定

- **テーマと言語**：ライト・ダークと表示言語を選びます。
- **ログイン時の起動**：端末にログインしたら使いたい場合に有効にします。
- **更新の自動確認**：新しいバージョンを確認します。
- **メニューバー / システムトレイ**：利用枠の表示内容とカウントダウン単位を選びます。

変更後は実際の表示を確認し、必要なウィンドウが読みやすく出ているか確かめます。値の意味は[利用枠ガイド](/ja/docs/quota/)を参照してください。

## ログと CLI の場所

**`CODEX_HOME`** は Codex ホームディレクトリであり、個別の JSONL ファイルではありません。空でない値は既定値を上書きし、Windows/WSL の自動検出を無効にします。対象ログの場所がわかる場合に設定してください。

**`CODEX_CLI_PATH`** は CLI 実行ファイルまたはラッパーです。`codex`、`codex.exe`、`codex.cmd` などを指定し、自動検出できない独自のインストール先で使います。

一方はログの場所、他方は使う CLI を制御します。起動元のプロセスが環境変数を継承する必要があり、ターミナル内の設定がデスクトップアイコンから起動したアプリに届くとは限りません。

## 日次集計のタイムゾーン

**`CODEX_USAGE_TIMEZONE`** は日付の区切りを決めます。既定はシステムのタイムゾーンで、失敗時は UTC です。報告を揃える場合は `Asia/Shanghai` や `UTC` などを指定できます。

変更すると深夜の使用量が隣の日に移る場合があります。集計や出力の比較では期間とタイムゾーンを確認してください。

## 変更後の確認

1. 元に戻せるよう、変更前のディレクトリと期間を記録します。
2. 変数が起動環境に届くことを確認し、完全に終了して再起動します。
3. ログを再スキャンし、期間内のセッションとプロジェクトを確認します。
4. 記録が消えた場合は上書きを外して再起動し、[トラブルシューティング](/ja/docs/troubleshooting/)を確認します。
