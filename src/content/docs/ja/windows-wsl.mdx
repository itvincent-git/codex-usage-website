## このガイドの対象

Windows 10/11 x64 や WSL ターミナルで Codex を使う方向けです。通常はパスを設定せず自動検出できますが、どのログが選ばれるかを理解しておくと便利です。

## 検出の順番

1. アプリは **Codex ディレクトリを選択**で保存したディレクトリを優先します。次に、空でない `CODEX_HOME` が設定されていれば、そのディレクトリを使います。
2. ディレクトリの指定がない場合は、`%USERPROFILE%\.codex` の `sessions` と `archived_sessions` にある `.jsonl` と `.jsonl.zst` を調べます。
3. Windows 側にセッションファイルがなければ、既定の WSL ディストリビューションの `$HOME/.codex` を使用します。WSL を利用できない場合は Windows 側のディレクトリに戻ります。

重複を防ぐため、ネイティブと WSL のセッションや複数のディストリビューションは統合しません。

## WSL の作業が見つからない場合

普段使うディストリビューションが既定か確認します。Windows PowerShell の次の読み取り専用コマンドで一覧を表示できます。星印が既定です。

```powershell
wsl --list --verbose
```

対象のディストリビューションに Codex のセッションがあることを確認します。自動検出では、対応するセッションファイルが Windows 側に 1 件でもあれば、そちらのディレクトリが優先されます。

復旧パネルに **Codex ディレクトリを選択**が表示される場合は、`sessions` または `archived_sessions` を含む WSL 側の Codex ホームを選びます。選択は保存され、すぐに再スキャンされます。`CODEX_HOME` に `\\wsl.localhost\Ubuntu\home\example\.codex` のような Windows からアクセスできるパスを指定することもできます。適用方法は[詳細設定](/ja/docs/advanced-settings/)を参照してください。

## インストールと現在の利用枠

インストーラーは現在のユーザー向けです。Authenticode 署名がまだないため SmartScreen が警告する場合があります。[ダウンロードページ](/ja/download/)から案内されるプロジェクトの GitHub Release が配布元か確認してください。

セッションが見えて利用枠が出ない場合は、アプリが使う環境の CLI がログイン済みか確認します。ログ取得と利用枠取得は別の処理です。詳しくは[トラブルシューティング](/ja/docs/troubleshooting/)を参照してください。
